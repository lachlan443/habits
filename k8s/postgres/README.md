# Postgres on Kubernetes (CloudNativePG)

Optional manifests for running a replicated Postgres for Habits with
[CloudNativePG](https://cloudnative-pg.io/) (CNPG). Nothing here changes how the
app runs by default: without `DATABASE_URL` Habits keeps using SQLite at
`DB_PATH`, exactly as before.

> Postgres support in the app is being added as part of the HA / Kubernetes
> tracker (#83, starting with #85 and #77). Until those land the app ignores
> `DATABASE_URL`, but you can already deploy and test the cluster below.

| File | What it creates |
|---|---|
| `cluster.yaml` | `Cluster` `habits-db`: 3 instances (1 primary, 2 replicas), synchronous replication to at least one replica, WAL archiving through the Barman Cloud plugin |
| `pooler.yaml` | `Pooler` `habits-db-pooler-rw`: 2 PgBouncer pods (transaction mode) in front of the primary |
| `objectstore.yaml` | `ObjectStore` `habits-db-backup`: S3-compatible bucket for base backups and WAL, 30 day retention |
| `scheduled-backup.yaml` | `ScheduledBackup` `habits-db-daily`: daily base backup at 03:00 UTC, plus one right away |
| `kustomization.yaml` | Applies all of the above |

No secrets are committed. The database password is generated by the operator,
and you create the S3 credentials yourself.

## Prerequisites

1. The [CloudNativePG operator](https://cloudnative-pg.io/documentation/current/installation_upgrade/)
   (1.26 or later).

2. The [Barman Cloud plugin](https://cloudnative-pg.io/plugin-barman-cloud/)
   (needs cert-manager), which handles backups and WAL archiving. The older
   in-tree `spec.backup.barmanObjectStore` is deprecated in CNPG, so it is not
   used here.

3. An S3-compatible bucket (AWS S3, MinIO, Cloudflare R2, Backblaze B2, ...).

## Deploy

```sh
NS=habits
kubectl create namespace "$NS"

# S3 credentials for backups (do not commit these)
kubectl -n "$NS" create secret generic habits-db-backup-s3 \
  --from-literal=ACCESS_KEY_ID=... \
  --from-literal=ACCESS_SECRET_KEY=...

# Edit destinationPath / endpointURL in objectstore.yaml first, then:
kubectl -n "$NS" apply -k k8s/postgres

kubectl -n "$NS" get cluster habits-db        # wait for "Cluster in healthy state"
kubectl -n "$NS" get backup                   # first backup should complete
```

For AWS S3 remove `endpointURL`. Adjust `storage.size`, `storageClass` and
`resources` in `cluster.yaml` for your cluster.

## How the app gets its `DATABASE_URL`

The operator creates these Services and a Secret in the same namespace:

| Name | Use |
|---|---|
| `habits-db-pooler-rw` | PgBouncer → primary. **Use this for the app.** |
| `habits-db-rw` | Primary directly. Use for migrations and anything that needs session state. |
| `habits-db-ro` / `habits-db-r` | Replicas only / any instance (read-only use). |
| Secret `habits-db-app` | `username`, `password`, `dbname`, `host`, `port`, `uri`, ... for the `habits` owner role |

**Through the pooler (recommended for the app).** The `uri` key in the secret
points at `habits-db-rw`, so build the URL from the username and password
instead. Kubernetes expands `$(VAR)` from earlier env entries:

```yaml
env:
  - name: DB_USER
    valueFrom:
      secretKeyRef: { name: habits-db-app, key: username }
  - name: DB_PASSWORD
    valueFrom:
      secretKeyRef: { name: habits-db-app, key: password }
  - name: DATABASE_URL
    value: postgresql://$(DB_USER):$(DB_PASSWORD)@habits-db-pooler-rw:5432/habits
```

The operator-generated password is alphanumeric, so it needs no URL escaping.
If you bring your own password with special characters, percent-encode it.

**Directly to the primary** (simpler, no pooling; also what a migration Job
should use, since PgBouncer runs in transaction mode):

```yaml
env:
  - name: DATABASE_URL
    valueFrom:
      secretKeyRef: { name: habits-db-app, key: uri }
```

Both Services always follow the current primary, so failover needs no app
changes; connections are dropped and must be re-established.

## Backups and restore

WAL is archived continuously to the bucket and a base backup runs daily, so you
can restore to any point in the last 30 days. Trigger an extra backup with:

```sh
kubectl -n "$NS" cnpg backup habits-db --method plugin --plugin-name barman-cloud.cloudnative-pg.io
```

To restore, create a new `Cluster` that bootstraps from the object store; see
[Recovery](https://cloudnative-pg.io/plugin-barman-cloud/docs/usage/#restoring-a-cluster)
in the plugin docs.
